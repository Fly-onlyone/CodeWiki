# CodeWiki — agent instructions

CodeWiki is a Windows-only native desktop app plus a Rust backend that generates and maintains a codebase wiki (an Obsidian vault at `<repo>/obsidian/`) for humans and coding agents. `ROADMAP.md` records what is built and what is verified.

## Hard rules

- **Licenses.** No AGPL, GPL, LGPL or EPL dependencies. `cargo deny check licenses bans sources` must pass. `merman` is used with `default-features = false`; the `forceatlas2` crate is banned.
- **No WebView.** The UI is native Rust on GPUI (`gpui-kit`). Do not add a browser, WebView2 or Electron dependency.
- **The app talks HTTP only.** `codewiki-app` gets all data from the backend through `cw-client`. It may link `cw-illustrate`, `cw-mermaid` and `openui-lang` to draw, never the index, parser or wiki crates.
- **Never overwrite a human-edited note.** Changes to such notes go through the proposal queue.
- **The index is a cache.** Everything in it must be rebuildable from the repository and the vault. Bump `SCHEMA_VERSION` in `crates/cw-index/src/schema.rs` on any schema change; old indexes are dropped and rebuilt.
- **Keep builds small.** Do not loosen the `[profile.dev]` settings in the root `Cargo.toml`; debug builds once reached 44 GB. Run `pwsh scripts\clean.ps1` after long sessions.

## Layout

| Path | Holds |
|---|---|
| `crates/cw-core` | Shared types, hashing, paths, errors |
| `crates/cw-parse` | Symbol extraction (Rust, Python, TypeScript, JavaScript, Java), name resolution, repository scan |
| `crates/cw-graph` | Graph metrics, communities, layout |
| `crates/cw-index` | SQLite index, full-text search, vectors |
| `crates/cw-embed` | Embedders for semantic search |
| `crates/cw-vault` | Note model, name registry, linter, manifest, proposals |
| `crates/cw-wiki` | Planning, rendering and generation of notes; every analysis |
| `crates/cw-llm` | LLM providers, prose writer, answers, illustrations |
| `crates/cw-illustrate`, `crates/openui-lang` | Illustration component library and its language |
| `crates/cw-mermaid` | Mermaid to SVG and PNG |
| `crates/cw-server` | HTTP API |
| `crates/cw-client` | HTTP client used by the app and the MCP bridge |
| `crates/codewiki` | CLI and `serve` |
| `crates/codewiki-mcp` | MCP stdio bridge |
| `crates/codewiki-app` | Desktop app |
| `plugins/` | Claude Code plugin and Codex configuration |
| `scripts/` | Packaging, install, uninstall, cleanup |
| `spikes/` | Finished experiments, outside the workspace; results in `spikes/VERDICTS.md` |
| `obsidian/` | CodeWiki's wiki of itself, generated by `codewiki update` |

## Adding a feature

A backend feature usually touches four places: the logic in `crates/cw-wiki/src/`, a route in `crates/cw-server/src/api.rs`, a subcommand in `crates/codewiki/src/main.rs`, and a tool in `crates/codewiki-mcp/src/main.rs`. An app page is a Markdown builder in `crates/codewiki-app/src/pages.rs` plus a palette entry in `palette.rs`.

## Commands

```
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo deny check licenses bans sources
```

Run all four before reporting work as complete.

## Verifying third-party APIs

Check crate APIs against docs.rs or the crate source for the pinned version before using them. GPUI is pre-1.0 and exact-pinned; do not bump it as a side effect of other work.

## Checking the app without taking focus

Start `codewiki-app <repo> <view>` where `<view>` is a note name or one of `graph:`, `palette:<query>`, `edit:<note>`, `settings:`, `themes:`, `health:`, `contracts:` and similar. Capture the window with `PrintWindow` and post input with `PostMessage`; do not bring the window to the front, and never capture the whole screen.
