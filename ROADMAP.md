# CodeWiki roadmap

Status as of 2026-11-27. "Verified" means covered by automated tests or by a live run recorded here or in `spikes/VERDICTS.md`. "Seen" means checked by eye on a window-only screenshot. 

## Current state

- 17 crates. `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` (1269 tests) and `cargo deny check advisories bans sources` all pass. The licenses of dependencies are no longer checked, by the owner's decision of 2026-11-20.
- Not released yet (2026-11-27), for 0.6.0. None of it had a run in the clean VM:
  - what becomes of a note when its code is deleted or moved, and linked git worktrees that are no longer projects ("M6 Notes of code that is gone" and "M6 Linked worktrees" below);
  - more languages (the P5 rows below): every language without a parser mapped at file level, parsers for C#, Go, Kotlin, C and C++, TypeScript path aliases, whole Python packages without `__init__.py`, pnpm, yarn and bun, and impacted tests for every mapped language.
- Version 0.5.0 is the sixth release (2026-11-26), built by CI from the tag `v0.5.0`. It brings:
  - "Notes per session" for auto explaining;
  - tab tools: right-click menus on tabs and sidebar notes, middle-click and Ctrl+click, a scrolling tab strip, and a Tabs card in Settings → Appearance;
  - a toolbar that fits a narrow window;
  - fixes: the Code health Score column, the title on Home, a right-click that left a row highlighted, folder links on the wiki map that said "not found", and notes stuck waiting after a sync that changed no fact.

  Each ran in the clean VM ("M11 Release run of 0.5.0").
- Version 0.4.0 was the fifth release (2026-11-26), built by CI from the tag `v0.4.0`. Its new features:
  - toasts and Windows notifications;
  - automatic reconnect to the backend and to the embedding server;
  - the Review page with several proposals decided at once;
  - search suggestions;
  - the background graph and the stronger hover, press and selection;
  - auto explaining with claims and the Waiting notes page;
  - an uninstaller that asks whether to delete data and settings.

  Each ran in the clean VM ("M11 Release run of 0.4.0").
- Version 0.3.1 was the fourth release (2026-11-22), built by CI from the tag `v0.3.1`. It adds a setup program beside the zip (`CodeWiki-0.3.1-windows-x64-setup.exe`, M11 Setup program), a list of folders kept from coding agents (`codewiki agents`, Settings → Repositories, Home and the palette), and `url` 2.5.9 for RUSTSEC-2026-0592. On the owner's word (a minor release) it had no release run in the clean VM: the four checks, CI and the release workflow passed, and the setup program's cases had run in the guest the same day (M11 Setup program).
- Version 0.3.0 was the third release (2026-11-22): a Windows zip on GitHub Releases and a backend image on GHCR, both built by CI from the tag `v0.3.0`. It replaces the built-in writer with notes a coding agent explains through the plugin (M12), and the built-in embedding model with the local servers a user runs (LM Studio, Ollama, llama.cpp, Lemonade, mistral.rs; M7), and adds opt-in error reports to Sentry, the agent view, the diagram viewer, zoom and "Open the last repository". Each of those servers was run for real in a clean Windows and compared ("Embedding servers compared" below). 0.2.0 was the second release, on 2026-11-18; 0.1.0 the first, on 2026-11-15.
- CodeWiki documents its own repository: 311 notes, 100% of wikilinks resolve, a second sync writes nothing.
- The Docker image builds (271 MB) and was exercised over HTTP and through the MCP bridge.

## Deviations from the original plan

- **No model of its own.** The plan had no neural model without Ollama or a key. A built-in model, run with `candle` in a worker process, was added and then removed on 2026-11-21: the user now runs the server (LM Studio, Llama for Windows, Lemonade, mistral.rs or Ollama) and CodeWiki asks it, so any embedding model can be used and CodeWiki does not own an engine.
- **Embeddings.** The default embedder is `local`: it hashes words, word pairs and character trigrams into a 384-dimension vector. It needs no model file and works in Docker, and it finds other forms of the words typed, but it does not know that two unrelated words mean the same thing. A neural model comes from a model server (`CODEWIKI_EMBED`). `fastembed` and `sqlite-vec` are not used; vectors are compared in Rust.
- **Editor.** The plan asked for an in-place live-preview editor. What exists is a source editor with a live preview beside it.
- **Installer.** A zip with PowerShell install and uninstall scripts and `.cmd` launchers for them, and a setup program (Inno Setup 6) that runs the same scripts, not an MSI.
- Community detection is Louvain, not Leiden.
- Git access uses the `git` command line, not `gix`.
- Notes are rendered by Rust code in `crates/cw-wiki/src/render.rs`. There is no template pack and no `restyle` command.
- A flow in a picture is drawn in rows of at most three boxes, each followed by its arrow. An arrow cannot turn down to the next row, so the arrow after a row's last box and the numbers on the boxes carry the order.
- Inheritance in Python, TypeScript, Java and Kotlin is stored as an `implements` edge; there is no separate `extends` kind.

## Known issues

- Search with the embedder that needs no model (`local`) ranks by shared words and word stems; a query such as "resolving names" can put a loosely related symbol first.
- With Ollama (0.40.17, on the processor) a search by meaning often takes about two seconds: Ollama takes that long for any request whose length in tokens it has not seen since it loaded the model, and queries differ in length. Its own log shows it, and the benchmark's plain requests hit it too. The other servers answered in under 100 ms.
- A clean Windows has no Visual C++ runtime, which `llama-server`, Lemonade's `llama-server` and mistral.rs need; LM Studio's command-line installer fails when `TEMP` is a long path; mistral.rs on the processor needs about 2.6 GB free for `Qwen3-Embedding-0.6B` unless started with `--isq 8`. README says so. None of these servers is CodeWiki's.
- `codewiki search` on the command line is full-text only, as before: it does not ask the embedder. Search by meaning is in the app, over HTTP and through the MCP tools.
- Dead-code findings in Python, TypeScript, JavaScript, Java, Kotlin, C and C++ are reported as "possible", never "likely", because dynamic dispatch hides references from a static index.
- The editor has no Markdown syntax colouring. The UI kit's Markdown highlighter needs a different `tree-sitter` version than the parsers use, and Cargo cannot select both.
- A CodeWiki up to 0.5.0 cannot read a retire proposal (a kind it does not know) and loads a repository's notes and proposals together, so it fails to open a repository whose vault holds one. It matters only where a newer build synced a vault that an older app then opens; decide the proposal with the newer build, or update the app.
- A note written by hand that names files that are gone beside one file that exists stays as it is, and the sync only lists it. A file such as `README.md`, named in passing, is enough to keep the note.
- Two hand-written notes with one name: only the first is managed. The second is judged once the first is gone, so its retirement is proposed one sync later.
- Still missing from phase 2: nothing on the first list. Not read: bundler aliases (`vite.config.ts`, webpack), `bun.lockb`, a `tsconfig.app.json` that a `tsconfig.json` only lists in `references` (see "P5 Python, TypeScript and JavaScript").

- In a small, sparse graph (54 nodes, 20 edges for `cw-core`) the layout puts linked nodes on top of each other, so an edge is shorter than the dots it joins and none shows; labels of such nodes overlap. The edges are drawn, and show on this repository's graph of 2,063 nodes. It needs other ForceAtlas2 settings for small graphs in `cw-graph`, which changes every layout.
- A plain `.\install.ps1` is still refused by Windows's default script policy; that is the policy, and `install.cmd` is the way around it.
- The programs are not signed. Where an administrator has turned on Defender's attack surface reduction rules "Block executable files from running unless they meet a prevalence, age, or trusted list criterion" or "Use advanced protection against ransomware", Windows refuses to start a build that Microsoft's cloud does not know yet: "Access is denied". Seen on 2026-11-16 and 2026-11-18: a build of minutes ago and the published 0.1.0 were refused; a build that had run in the same guest two days before was let through. Windows ships with both rules off. A signature Windows trusts would end it. On 2026-11-25, under `-Hardened`, the same rule refused parts of the 0.4.0 build a few hours after it was built:
  - `codewiki-mcp.exe`, so Claude Code's plugin did not connect (`EPERM ... uv_spawn`);
  - the setup program;
