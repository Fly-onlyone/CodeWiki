# Refactor Module

> Refactoring plan: suggestions derived from facts the index already holds.

## What it does

Turns facts the index already holds into refactoring suggestions. Nothing here is generated by a model. Each suggestion comes from a measurable condition (a long file, a type with many methods, files that depend on each other in a cycle, a function whose collaborators all live in another file), states the evidence, and lists steps in the order that keeps the code compiling between them. The same index always yields the same plan. The app, the CLI and the API show it.

## Source

- `crates/cw-wiki/src/refactor.rs` — module `cw_wiki::refactor`

## How it works

`plan` loads `Facts` once: all symbols sorted by name, the dependency links between them as index pairs, hotspot scores per file, the files that depend on each file, and the crate directories. Then four detectors each add `Suggestion`s to one list:

1. `split_files` takes files that the health check flags as long or as reaching into many others (test files skipped). It finds the types with their methods that span 60 or more lines, and groups of 3 or more free functions that share a name prefix. The largest type stays. The steps move up to 3 others into sibling files.
2. `extract_types` takes non-trait types with at least `MANY_METHODS` methods. It groups method names by prefix (4 or more share one), ignoring generic ones such as `get` or `new`. The biggest group becomes a helper type named after the owner and the prefix.
3. `break_cycles` builds a file-to-file graph from calls, type references and implementations. It finds strongly connected components of 2 or more files, and proposes cutting the link with the fewest references. A C or C++ header and the source of its name are not a cycle, since they call each other by design.
4. `move_functions` finds free functions with 3 or more links to one other file, none to their own file, and at most half as many links elsewhere. The file must be in the same crate.

`priority` mixes a base per kind with 30 percent of the hotspot score and up to 10 for reach. The list is sorted by priority, then kind, then target. Every suggestion ends with a verify step that runs the tests and clippy for the owning crate.

## Items

- `pub enum Kind` — public enum; used by `Suggestion`.
- `pub struct Suggestion` — public struct; used by `break_cycles`, `extract_types`, `move_functions`, `plan` and 2 more.
- `const GENERIC_PREFIXES: [&str; 12]` — Method-name prefixes that describe access, not a responsibility.
- `const MIN_GROUP: usize` — fewest methods sharing a prefix that make a group worth extracting.
- `const MIN_FUNCTION_GROUP: usize` — fewest free functions sharing a prefix that make a module.
- `const MIN_CLUSTER_LINES: u32` — A type and its methods must span this many lines to earn its own module.
- `const MIN_FOREIGN_LINKS: usize` — links to another file needed before a function is said to belong there.
- `fn lines_of(symbol: &Symbol) -> u32` — private function, returns `u32`; called by `extract_types`, `move_functions`, `split_files`.
- `fn snake(name: &str) -> String` — private function, returns `String`; called by `split_files`.
- `fn sibling(file: &str, stem: &str) -> String` — private function, returns `String`; called by `split_files`.
- `fn prefix_groups<'a>(names: &[&'a str], min: usize) -> Vec<(&'a str, Vec<&'a str>)>` — group names by their first `_`-separated word; groups of at least `min` names, largest first.
- `struct Facts` — facts shared by the detectors.
- `fn split_files(index: &Index, facts: &Facts, out: &mut Vec<Suggestion>) -> Result<()>` — long files and files that reach into many others.
- `fn extract_types(facts: &Facts, out: &mut Vec<Suggestion>)` — types with many methods.
- `fn are_header_and_source(a: &str, b: &str) -> bool` — A C or C++ header and the source of its name call each other by design: the symbols a header declares stand at the header, and the code that defines them is in the source. That is no loop to break.
- `fn break_cycles(facts: &Facts, out: &mut Vec<Suggestion>)` — files that depend on each other through calls, type references or trait implementations. `use` re-exports alone do not count.
- `fn move_functions(facts: &Facts, out: &mut Vec<Suggestion>)` — free functions that only work with code in one other file.
- `pub fn plan(index: &Index) -> Result<Vec<Suggestion>>` — every suggestion, highest priority first.

And 6 more private items with no comment.

## Gotchas

- Test paths are skipped everywhere through `is_test_path`.
- Free functions in `main.rs` or `build.rs`, functions named `main`, and functions with any attribute outside `PASSIVE_ATTRS` are never proposed for a move, since an attribute may register them.
- A function with even one link to its own file stays put.
- Cycle detection ignores plain `use` re-exports. Only real dependency edges count.
- Steps name files and helper types by rule (snake case, camel case). The names are starting points, not checked for clashes.
- The plan is only as good as the index. A stale index gives stale suggestions.
